# คู่มือฟีเจอร์ใหม่

## เปิดระบบ

- ใช้งานปกติและพิสูจน์ข้อมูลคงอยู่: `python run.py` หรือ START_WINDOWS.bat
- ซ้อมด้วยฐานข้อมูลใหม่แยกจากของเดิม: `python run.py --demo-session` หรือ START_DEMO_WINDOWS.bat
- ทั้งสองแบบเปิด http://127.0.0.1:8000; ถ้าชนพอร์ตใช้ `--port 8001`
- โหมดซ้อมคงข้อมูลระหว่าง reload แต่ทิ้งเมื่อปิดเซิร์ฟเวอร์ โหมดปกติเก็บข้ามการปิดเปิด

## คิวทบทวน → บันทึกนโยบาย → สร้างคำขอ

1. เลือกสาธิตย้อนหลัง เปิด “คิวทบทวน” เลือก SKU-0005
2. สังเกตสถานะ review และยังไม่มีแบบฟอร์มสร้างคำขอ
3. เปิดหน้าคุณภาพข้อมูลเพื่อดูต้นเหตุ: target 30 กับ 40 ขัดแย้ง (หรืออธิบายจาก quarantine.csv)
4. ในช่องนโยบาย กรอกขั้นต่ำ 10 เป้าหมาย 30 ระยะจัดหา 7 ผู้ทบทวนและเหตุผล เช่น “สมมติฐานสำหรับสาธิต: ทีมเลือกเป้าหมาย 30 ตามนโยบายฐาน ไม่ใช่ค่าจากยอดขายจริง”
5. บันทึกนโยบาย ระบบอ่านกลับ แสดง v1 และแนะนำเติม 29 เพราะคงเหลือ 1
6. สร้างคำขอ 29 แล้วเปิดแก้เป็น 28 บันทึก อ่านกลับเป็น v2
7. เปิดประวัติคำขอ และเปิดสินค้าจากหน้าสต็อกเพื่อดูประวัตินโยบาย

เมื่อแก้นโยบายแล้ว ยังไม่ใช่การแก้ stock snapshot หากสต็อกเก่าหรือผิด ระบบยังหยุด รายการ quarantine เดิมยังเก็บไว้เพื่อเป็นหลักฐานก่อนแก้

## What-if

เลือกสินค้าที่ผ่านการตรวจ (เช่น SKU-0001) ปรับเฉพาะช่องเป้าหมายเป็น 50 แล้วกด “ทดลอง What-if (ไม่บันทึก)” ผลแนะนำ 25 → 45 โดยไม่เปลี่ยน evidence ที่บันทึกจริง ปิด/เปิดสินค้าแล้วเป้าหมายยัง 30

ปุ่ม What-if ไม่บันทึกทั้ง policy หรือ request และปฏิเสธรายการที่ยัง review กรอกตัวเลขทั้ง 3 ช่องให้ครบ แต่ไม่ต้องใส่ชื่อ/เหตุผลถ้าเพียงทดลอง

## API ที่เพิ่ม

POST `/api/policy-reviews`:

```json
{"product_id":"SKU-0005","location_id":"BKK-DC","mode":"demo","min_qty":10,"target_qty":30,"lead_days":7,"version":0,"reviewer":"Demo reviewer","reason":"Team-approved synthetic policy for demonstration"}
```

version 0 = ยังไม่มี override; ใช้ policy_version ล่าสุดจาก GET risks สำหรับการแก้ครั้งต่อไป ถ้าเก่า → 409 ไม่เขียนทับ

POST `/api/what-if` ใช้ product_id, location_id, mode, min_qty, target_qty, lead_days; ไม่ต้องส่ง version/reviewer/reason

GET `/api/policy-history/SKU-0005?mode=demo&location=BKK-DC` อ่านประวัติ policy; GET `/api/project` อ่านผลเทียบต้นฉบับ

## สิ่งที่ยังไม่เพิ่มโดยตั้งใจ

ยังไม่มีการสั่งซื้อจริง ระบบยืนยันตัวตน การแก้ยอดสต็อกผ่าน UI หรือ demand forecast
